# 微软淘汰的 IE 技术，信创用了不安全？答案在这里

上一篇文章《最尴尬的信创现状：我们在全力兼容微软已经废弃的技术》发布后，引起了读者朋友的热烈反响。抛开网络中的各类争议，这里回答一下某些朋友关心的问题，比如有位朋友就问道：

> 微软弃用 IE 技术体系的核心是因为安全问题，那么由 wine 去完成兼容适配的话，以前伴随着的安全问题还存在吗？

关于这个问题，我们需要有一个共识：**所有网络安全风险，都是场景化的风险，脱离应用场景谈安全漏洞，都是片面且不客观的。**

简单说 ActiveX 不安全是不严谨的。众所周知，国内各大银行的网银安全控件、金融交易系统已基于该技术稳定运行十余年，从未出现因控件本身漏洞导致的用户资金损失、数据泄露问题。与此同时，政务审批平台、各行业专属业务系统等核心政企场景，依托IE、ActiveX技术落地运行，也从未爆发大规模安全事故。

而大家诟病 IE 和 ActiveX 不安全，核心原因是其权限开放度高、适配门槛低，在开放环境中极易被恶意程序利用，而这一风险的专属触发场景，正是公共互联网。

在互联网场景下，用户可随意访问陌生网页、加载未知控件，而ActiveX拥有极高的系统操作权限，一旦遭遇恶意脚本、木马程序植入，漏洞会被快速触发，安全风险被无限放大。

但信创行业的落地场景完全不同：信创体系下的 ActiveX 控件，仅服务于固定的政企核心业务流程，功能高度单一、使用边界清晰、调用规则固定，不存在随意加载、未知调用、恶意触发漏洞的应用基础。

换言之，IE、ActiveX 等老旧技术的固有缺陷，在专属化、规范化、封闭化的信创业务场景中，彻底失去了被攻击、被利用的条件，自然不会产生实质性安全风险。

## 01 内网隔离部署，从根源阻断外部攻击风险

参与过信创项目落地的读者朋友应该对此深有体会。

目前国内政务、国企、金融、能源等核心信创落地场景，所有核心业务系统均部署在专属内网环境，全程采用物理隔离、专线独立运维模式，完全不接入公共互联网，这是抵御老旧技术安全风险的核心屏障。

微软原生Windows环境中，IE的绝大多数安全漏洞，均由外网渗透、跨网攻击、恶意网页传播引发。黑客通过互联网扩散恶意脚本与木马，利用IE及ActiveX的架构漏洞，实现远程设备控制、核心数据窃取、系统权限篡改等恶意操作，风险源头完全来自外网开放环境。

而信创内网场景从根本上规避了这一风险：封闭内网无外部恶意流量接入、无陌生网络访问请求，外部黑客无法穿透物理隔离网络发起攻击。即便适配复用的IE技术体系存在原生老旧漏洞，也没有被触发、被利用的网络环境与攻击条件。

与此同时，信创内网配套完善的分级权限管控、全流程日志审计、终端安全管控体系，业务访问、组件调用、系统操作全程可追溯、可监管、可溯源，彻底杜绝内网违规操作、恶意入侵的可能性，从环境层面锁死老旧技术的安全隐患。

像好莱坞大片《虎胆龙威4》中那种黑客控制交通、电力、电信等核心部门的场景，也只会出现在电影中，现实中绝不可能出现。

## 02 组件来源完全可控，杜绝未知安全后门

事实上，ActiveX等IE体系老旧组件的安全风险，根源是未知、未审核的恶意第三方组件，而非技术架构本身存在原罪。

在信创Wine兼容适配方案中，所有投入使用的ActiveX控件、IE体系核心组件，均为各行业核心业务专属定制开发、官方合规交付，绝非互联网上随意下载、来源不明、未经审核的第三方插件。

这类政企专属业务组件，落地前需经过需求精准梳理、全量代码审计、多轮安全渗透测试、合规资质核验等一系列严苛流程，无隐藏后门、无多余系统权限、无冗余无效功能，仅保留支撑核心业务正常运行的最小必要能力。相较于互联网场景中随意获取的未知组件，其安全性、稳定性、可控性实现了量级提升。

简单来说，原生Windows互联网环境的安全风险，本质是技术高度开放带来的滥用风险；而信创场景下，组件专属定制、业务流程固定、系统权限可控，从源头杜绝了恶意组件入侵、原生漏洞被滥用的可能。

## 03 多数安全隐患，本质是「信任问题」而非技术问题

市面上绝大多数所谓“老旧技术安全问题”，剥开技术表象来看，本质不是技术漏洞问题，而是信任边界失控的问题。

微软之所以全面废弃IE与ActiveX技术体系，并非该技术本身完全不可用，而是在开放、多元、无边界的互联网生态中，微软无法管控海量用户的使用行为，无法甄别全网数以万计的第三方组件的安全性，信任边界无限扩张，漏洞滥用风险彻底失控，最终不得不全面淘汰。

而信创基于Wine的兼容适配方案，彻底重构了一套封闭、可控、合规的全新信任体系：

* 网络层面：以内网物理隔离划定绝对安全的信任边界，隔绝一切外网未知风险；
* 权限层面：以分级授权、最小权限原则规范所有操作行为，杜绝越权操作；
* 组件层面：以专属定制、全量审计锁定安全底线，无未知风险组件；
* 场景层面：以固定专属业务规避漏洞触发条件，无滥用场景基础。

没有失控的信任边界、没有开放的滥用环境、没有未知的风险组件，即便沿用外网已经淘汰的IE技术体系，也不会产生实质性安全隐患。

## 写在最后

技术新旧迭代，从来不是评判安全与否的核心标准，适配的应用场景、完善的管控体系、可控的技术来源，才是网络安全的核心基石。

信创通过Wine兼容微软废弃的IE、ActiveX技术，并非盲目固守老旧技术、滞后技术迭代，而是在可控、封闭、合规的政企内网专属场景下，实现老旧核心业务系统的平稳迁移、无缝适配，在保障业务连续性、降低替换成本的同时，完全兼顾场景专属安全性。

在国产信创全面推进的进程中，始终存在一个争议： Windows 系统成熟稳定、使用便捷，为何要费力替换为国产自主系统？本质上，这同样是一场信任博弈。如果我们可以无条件、永久信任境外技术平台不会留存后门、不会管控掣肘、不会出现安全风险，持续使用 Windows 自然无可厚非。但技术主权与数据安全，从来不能寄托于他人的善意，一旦外部信任崩塌，依赖境外技术体系的政企核心数据、业务系统，将面临无法承受的系统性风险。
